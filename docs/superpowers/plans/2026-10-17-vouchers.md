# Hotel Vouchers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Admin creates, saves, edits and prints "Service Confirmation" hotel vouchers, autofilled from bookings and the Hotel List.

**Architecture:** New `Voucher` Mongoose model + pure helpers in `src/lib/vouchers.ts`; JSON admin API under `/api/admin/vouchers`; admin pages under `(app)/vouchers`; standalone print page `/admin/voucher-print/[id]` outside the admin shell. HotelMaster gains address/contact.

**Tech Stack:** Next.js 16.3 App Router, React 19, Mongoose 9, Tailwind 4, react-icons, `tsx --test`.

**Spec:** `docs/superpowers/specs/2026-10-17-voucher-design.md`

## Global Constraints

- No commits/pushes without the user's go-ahead (branch `feature/rich-packages`). Dev DB `guidewala_app_dev` only.
- Voucher numbers `GW-V-0001` (4-digit zero pad, grows past 9999), sequential = highest existing + 1.
- Meal plans `EP, CP, MAP, AP`. Row status `Confirm, Pending, Cancelled`. Payment terms `Prepaid, Pay at Hotel, Partially Paid`. Nationality default `Indian`.
- Service label `"<nights>D/<nights>N"`; dates printed per night (check-in … check-out − 1) as `dd/mm/yyyy`.
- Company block (verbatim): "G8 Guidewala Services LLP", "+91 9829185267", "booking@guidewala.co.in", "Registered Office : 1st floor, E 69, Ganga Marg, Prem Nagar, Jhotwara, Jaipur, Rajasthan -302012". Title "Service Confirmation". Logo `/assets/img/logo11.png`.
- Admin UI kit `src/components/admin/ui.tsx` (Section, Card, Field, inputCls, Toggle, Badge, PageHeader, PrimaryLink, EmptyState, Loading).

## Review Focus

1. Check-out ≤ check-in → 400 with a clear message, never a negative/zero-night row.
2. Two vouchers created at the same moment must not share a number (unique index + retry on duplicate key).
3. Hotel deleted or renamed after a voucher was made → voucher still prints its saved snapshot.
4. Booking sources with missing phone/dates (vendor customers have no phone) still autofill what exists.
5. Print page prints only the voucher (no admin chrome, no buttons) on A4.

### Task 3: Voucher API

**Files:** Create `src/app/api/admin/vouchers/route.ts`, `src/app/api/admin/vouchers/[id]/route.ts`, `src/app/api/admin/vouchers/sources/route.ts`, `src/app/api/admin/vouchers/fields.ts`, `src/app/api/admin/vouchers/fields.test.ts`.

**Produces:** `parseVoucherBody(body: unknown): { ok: true; value: Omit<VoucherDoc,"VOUCHER_NO"|"CREATED_ON"|"UPDATED_ON"> } | { ok: false; error: string }` — guest name required, ≥1 row, each row hotel name + valid dates (check-out > check-in), enums validated, `SERVICE` defaults to `serviceLabel(nights)` when blank, strings trimmed. JSON body keys: `guestName, guestNote, nationality, contactNo, paymentTerms, source {type, refId}, notes, rows[{hotelId?, hotelName, address, checkIn, checkOut, service, mealPlan, status, refCode, contact}]`.
- `GET /api/admin/vouchers?q=` → `{ vouchers }` newest first, q matches VOUCHER_NO / GUEST_NAME / CONTACT_NO (escaped regex, case-insensitive), max 200.
- `POST` → 201 `{ voucher }`; number = `formatVoucherNo(max parseVoucherSeq + 1)`; on duplicate-key error retry up to 3 times.
- `GET/PUT/DELETE /api/admin/vouchers/[id]` (id = VOUCHER_NO) → 404 when missing; PUT replaces fields, keeps number/CREATED_ON, sets UPDATED_ON.
- `GET /api/admin/vouchers/sources?type=hotel|guide|vendor&q=` → `{ items: { refId, name, phone, guests, from, to, label }[] }` (max 20, newest first; q matches name/phone/booking id). Hotel: HotelBookingDetails (HOTEL_BOOKING_ID, CUST_NAME, PHONE_NO, NO_OF_GUESTS, ARRIVAL_DATE, DEPARTURE_DATE). Guide: PkgBookingDetails (BOOLING_ID, CUST_NAME, PHONE_NO, NO_OF_PASSENGERS, DOS). Vendor: VendorCustDetails (CUST_ID, CUST_NAME, no phone, STAY_FROM_DT, STAY_TO_DT). Bad type → 400.
- [ ] Unit-test `parseVoucherBody` (Review Focus 1, enums, defaults). Checkpoint: curl create two, list, search, edit, delete; sources for each type.
